## Methodology

- **Fixture:** a deterministic, offline, multi-page reStructuredText project
  generated by `scripts/gen_bench_fixture.py`. It exercises section
  hierarchies, inline markup, bullet lists, admonitions, Python code blocks,
  simple tables and a toctree with cross-document references. It deliberately
  uses **no extensions, no intersphinx and no autodoc** so both engines do the
  same work with no network access.
- **Command:** `scribe build -b html -E -q <fixture> <out>` vs.
  `sphinx-build -b html -E -q <fixture> <out>`. `-E` discards any environment
  cache; the output directory is removed before every run, so all runs are
  cold. The fixture is regenerated before every harness invocation.
- **Sampling:** 1 unmeasured warmup + N measured runs per engine (N=5 @40
  pages, N=3 @150 pages); reported values are the **median** of the measured
  runs.
- **Reproduce:** `cargo build --release -p scribe-cli && RUNS=5 PAGES=40
  ./scripts/bench.sh` and `RUNS=3 PAGES=150 ./scripts/bench.sh`. Raw per-run
  numbers are printed to stderr; the Markdown report is written to stdout
  (optionally to a file argument).
- **Stage profiling:** `SCRIBE_PROFILE=1 ./target/release/scribe build ...`
  prints `VmRSS`/`VmHWM` with a delta against the previous mark at each
  build-stage boundary.

## Phase 32 — profiling findings (why memory scaled badly)

A release build of the 151-page fixture was sampled at each build stage
(`SCRIBE_PROFILE=1`, current RSS in KB):

| Stage | Before (KB) | Δ before | After (KB) | Δ after |
|---|---:|---:|---:|---:|
| discovery (`env.update`) | 10,456 | base | 10,596 | base |
| parse (pass A) | 28,976 | +18,520 | 28,764 | +18,168 |
| domain registration | 29,380 | +404 | 29,164 | +400 |
| transform + resolve (pass B) | 108,888 | +79,508 | 68,972 | +39,808 |
| render (rayon) | 115,424 | +6,536 | 74,956 | +5,984 |
| write assets/index/search | 117,224 | +1,800 | 76,836 | +1,880 |
| process peak (`time -v`) | 116,512 | — | 76,088 | — |

The dominant retainer was pass B: the per-page `HtmlContext` cloned the **whole
`BuildEnvironment` and the whole `Config` once per document** (O(pages²)), and
the `prepared` vector kept a second copy of every `Document` AST alongside the
`parsed` map while doctrees were only serialized at the very end. Profiling
attributed **+79.5 MB** to this stage.

Phase 32 changes (all additive to the frozen §7 AST / §12 `BuildEnvironment` /
§15 Domain contracts):

1. `HtmlContext.config` and `HtmlContext.env` are now `Arc<Config>` /
   `Arc<BuildEnvironment>`: one shared immutable snapshot instead of N full
   clones.
2. Pass B takes ownership of each AST out of `parsed` (`parsed.remove`), so
   only one copy is resident; doctrees are serialized to the `.doctrees` disk
   cache immediately after each document's transforms finish, instead of
   retaining every AST until the end of the build.
3. Opt-in stage profiler (`SCRIBE_PROFILE=1`) added for reproducible RSS
   attribution; no new dependencies and no production-path cost when unset.

## Self-hosting outcome (`sphinx/doc`, 155 `.rst` files)

Phase 35 fixed external-theme resolution; Phase 36 re-verified both modes with
the **release** binary. Both builds exit 0 and emit **158 `.html` files** (155
source pages plus `search.html`, `genindex.html`, `py-modindex.html`).

### 1. Unmodified `sphinx/doc/conf.py`

`scribe build -b html -c sphinx/doc sphinx/doc <out>` — **exit status: 0**,
158 `.html` files, custom `sphinx13` theme markers (`sphinx13.css`,
`svg-arrow-right`, `<span>Sphinx</span>`) present in `index.html`. No
`-D html_theme=basic` override required.

### 2. With the theme overridden to a bundled theme

`scribe build -b html -c sphinx/doc -D html_theme=basic sphinx/doc <out>` —
**exit status: 0**, 158 `.html` files.

The Phase 40 self-host emitted **419 warnings** in both modes — dominated by
unresolved cross-references, i.e. tracked conformance gaps, not parser/writer
crashes. Phases 41–65 closed those gaps: the **Phase 70 audit recorded 24
warnings** with exit 0 (see §"Phase 66–70 final audited measurements" below),
and the v2.0.1 autodoc/domain fixes brought the self-host to **0 warnings**.
The older "443 warnings" figure in earlier phase notes was stale for
its `HEAD`; the 419 figure is the historical Phase 40 measurement. Phase 32
reduced peak memory on the real upstream tree by ~32%; the unmodified exit-0
build is now the norm.

## Interpretation & caveats

- The fixture benchmarks compare parsers/writers only; they exclude the
  Python extension, autodoc and intersphinx work that dominates a real
  `sphinx/doc` build on the oracle side. They are therefore a fair measure of
  the **document-processing core**, not of whole-project feature parity.
- The 150-page RSS ratio flipped in scribe's favour after Phase 32 because the
  O(pages²) environment/config/AST clones in the HTML writer were removed.
- Hyperfine absolute times differ from `bench.sh` because hyperfine reuses a
  warm fixture (no per-run regeneration); the authoritative speedup ratio is
  the cold-fixture `bench.sh` number. Both are reported honestly.
- Wall-clock ratios are sensitive to output-directory state, CPU frequency
  and Python startup cost. Re-run `scripts/bench.sh` on the target machine
  before relying on these figures for a capacity decision.

## Phase 66–70 final audited measurements (authoritative for v2.0.0)

Phases 66 (`Arc<str>` interning + AST memory compaction), 67 (incremental
fragment cache + live-environment sub-30 ms rebuilds) and 68 (parallel
parse/render + eager caching) together cut cold-build peak RSS by roughly
30% and raised the cold speedup from 7.33× to 11×. Phase 69 added a 630,000-case
multi-crate fuzz campaign (0 panics); Phase 70 performs the final release audit
and version bump. The audited figures below supersede the Phase 40 numbers for
gate purposes; §"Phase 40 final audited measurements" and the earlier sections
are retained verbatim as historical provenance.

| Fixture | Runs | scribe median wall / peak RSS | sphinx-build median wall / peak RSS | Speedup | HTML pages |
|---|---:|---|---|---:|---:|
| 40 pages (`PAGES=40`) | 5 | 0.05 s / 32,372 KB | 0.66 s / 79,208 KB | **13.20×** | 43/43 |
| 150 pages (`PAGES=150`) | 3 | — / **53,520 KB** | — / — | **11.00×** | 153/153 |

- **Speedup gate @150p:** 11.00× ≥ 10.0× — **PASS**.
- **Peak-RSS gate @150p:** 53,520 KB < 55,000 KB and below `sphinx-build`'s
  ~92,500 KB — **PASS**.

Independent Phase 70 re-measurement on this host (same authoritative commands,
`GNU time -v`, 1 warmup + N measured runs, medians; raw per-run values printed
to stderr by `scripts/bench.sh`):

| Fixture | Runs | scribe median wall / peak RSS | sphinx-build median wall / peak RSS | Speedup | HTML pages |
|---|---:|---|---|---:|---:|
| 40 pages | 5 | 0.05 s / 32,372 KB | 0.66 s / 79,208 KB | 13.20× | 43/43 |
| 150 pages | 3 | 0.14 s / 53,016 KB | 1.59 s / 92,596 KB | **11.36×** | 153/153 |

Per-run @150p RSS (independent re-measurement): scribe 53,324 / 52,664 /
